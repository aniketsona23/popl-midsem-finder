For each stack, start at its top, form a string using successive top-down elements, and stop at
the first null byte "\o'. What comparison keys are produced and what is the ascending order?
Input/scenario data
S1 top
S2 top
S3 top -> .P.
Estimated time:2-3 minutes
Each stack is read from the top, and characters are appended until the first null byte "o', which
acts as thestring terminator.
For Stack S1: string is formed as [c,a,t]. The element 'x' is not a part of the key and is never
read because it appears after/below thestring terminator'\o'.
For Stack S2: string is formed as [c,a,r].
For Stack S3: string is formed as [d,o,g].
Thus, keys produced:
S1: "cat"
S2: "car"
S3: "dog"
Comparing the keys produced lexicographically, ascending order: S2 ("car") < S1 ("cat") < S3
("dog").

In the context of the professor's module-independence exercise, give one potential modularity
advantageofDesignBoverDesignA.
Code/relevantfragment
//Design A
class MyListextends Storage{
//Design B
class MyList {
private Storage storage;
Estimated time:2-3minutes
The Design A suffers from the Fragile Base Class problem as mentioned in the "Goodbye,
OOP" article. MyList is dependent on Storage's implementation. All public methods of
Storage also become available in MyList, so users can access things that may not be
intended for use. An internal change in Storage can break MyList without MyList's code
changing.
In Design B (private Storage storage), MyList uses composition. MyList contains a Storage
object and uses its methods when needed. Users only see the methods provided by
MyList. This means Storage can be changed or replaced more easily without affecting the
users of MyList.
Thus, the advantage is that Design B keeps the two modules separate by hiding Storage
behind MyList's own interface.

inheriting from them. From the Goodbye, OOP article, Copier contains a Scanner and a Printer,

between the two inherited startO methods. This makes the code more flexible because Copier

Estimated time:2 minutes
With ++count, count increases before it is used as the array index. So the first record is stored
at records[1] instead of records[0]. This means the third insert tries to use records[3], which is
outside the array and causes an ArraylndexOutOfBoundsException. Therefore, only 2 records
