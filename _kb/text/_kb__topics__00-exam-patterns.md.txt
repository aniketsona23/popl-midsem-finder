# How this professor sets and grades questions (read this first, 3 min)

## In plain words

This page is about how the professor marks, not about a subject. He wants you to explain why something happens (a reason), in the words used in class, and in exactly the format the question asks for.

**Example.** if a question says "one line each", write one line each. If it gives a table, fill the table and nothing else.


## Short answer

* He rewards first-principles reasoning (compiler, linker, loader, run time), not quotes from standards. *[2024 Mid-Sem key A2]*
* Follow the answer format exactly: tables, one line each, units. Overwriting or contradictions lose marks. *[2025 Mid-Sem paper]*
* Do not hunt syntax errors; the questions are about types, modules and procedure activation. *[2024 Mid-Sem paper note]*
* For assignment questions answer about your own implementation and stay consistent. *[2025 Mid-Sem Q3; Compre 2025 Q2]*

## What gets rewarded (quoted from the solution/notes)
* **First-principles over authority.** 2024 A2: "Those who cited a particular (ISO) standard … may or may not get credit." Reason from *compiler vs linker vs loader vs run time* and *type information (size/layout) vs names*.
* **Don't hunt syntax errors.** The paper says so: "do not smell a rat there. The questions are about type systems, modular structure and procedure activation." The code looks weird on purpose (`this`, `...`, shadowed `object1`).
* **Follow the answer format exactly** (tables, "α ↔ n", one line each). "Overwriting, unclear marking … will be interpreted as per the examiners' choices." "Consistency is important: something cannot be necessary yet harmful."
* **Brevity + precision.** "no more than 2 sentences each", "exactly 1 line each". "Jargon-bubble fables … will entail penalty."
* **Consistency with your own submission** for assignment-based questions (Q3 2025, Q2 compre 2025): answer about *your* design, say what you actually did.
* **Both sides of a trade-off.** Design questions: name the property (independence, fragile base class, flexibility), state which design wins *and the condition under which the other would*.

## 60-second triage for a *new* question
1. Is code given? → save it to files and check it with gcc: `gcc -c -Wall A.c B.c`, `nm A.o B.o`, `gcc A.o B.o` (real evidence).
2. Which idea above? → open that cheat sheet; run `python _kb/search.py <keywords>` for the professor's own wording (slides + solutions).
3. Write with `_kb/answers/TEMPLATE.md`: *one-line verdict → reason in the course's vocabulary → evidence (tool output / line numbers) → exceptions*.
4. Re-read the question's **format instruction** before pasting. Count marks vs. effort: 10 marks ≈ 8–10 minutes in a 90-minute/70-mark paper.

## Time budget (90 min, ~70 marks)
Read all questions 3 min → easy 1-line questions first → code-analysis questions with the tool running in a terminal while you write others → last 5 min: formatting check (tables, line numbers, units: "bytes" or "multiples of sizeof(void*)").
